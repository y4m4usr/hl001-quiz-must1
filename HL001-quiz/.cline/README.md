# Cline設定ディレクトリ

このディレクトリには、Clineの動作を最適化するためのガイドラインと設定が含まれています。

## ファイル一覧

### `workflow-rules.md`
Clineが「ほぼ全自動」で効率的にタスクを実行するための詳細なガイドラインです。

**主な内容:**
- タスク分解の方法（5-15分粒度）
- 実行サイクル（Goal定義 → 設計 → 実装 → テスト → レビュー）
- セキュリティチェックリスト
- エラーハンドリング戦略
- ツール選択の優先順位
- 推奨技術スタック（2025年10月時点）
- 実践的なワークフロー例

## 使い方

### 初回セットアップ
このディレクトリは既に設定されています。Clineは自動的にこれらのガイドラインに従って動作します。

### ガイドラインの確認
```bash
# ワークフローガイドラインを確認
code .cline/workflow-rules.md
```

### カスタマイズ
プロジェクト固有のルールを追加したい場合：

1. `workflow-rules.md` を編集
2. プロジェクト固有の制約や規約を追加
3. Clineは次回のタスクから新しいルールに従います

## 重要なポイント

### ✅ 自動化されていること
- タスクの自動分解（5-15分単位）
- 進捗のチェックリスト管理
- エラー時の自動リトライ（最大3回）
- セキュリティチェックの自動実行

### 🔒 安全性の確保
- すべての変更はDiffで可視化
- コマンド実行は適切な承認フロー
- 機密情報は.envで管理
- Git履歴での変更追跡

### 📊 推奨技術スタック
- **フロントエンド**: Next.js + Tailwind CSS + shadcn/ui
- **バックエンド**: Supabase + Next.js API Routes
- **デプロイ**: Vercel
- **開発ツール**: VS Code + Cline + Continue + Ollama

## Windows環境での注意事項

⚠️ **重要**: npm CLIツール `cline` はWindowsで利用できません（macOS/Linux専用）

✅ **現在の環境**: VS Code拡張機能の **Cline** を使用中（Windows完全対応）

## トラブルシューティング

### Clineが期待通りに動作しない場合
1. `workflow-rules.md` の内容を確認
2. VS Code拡張機能のClineが最新版か確認
3. 必要に応じてClineを再起動

### ガイドラインを無視したい場合
特定のタスクでガイドラインを適用したくない場合は、タスク指示時に明示的に指定してください。
