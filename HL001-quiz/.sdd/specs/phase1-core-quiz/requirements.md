# 要件定義書（phase1-core-quiz）

## 機能概要
Google Apps Script と Google Sheets を用いて、カラコン商品の識別力を鍛える社内向けクイズ学習サービス「カラコンアカデミア」のフェーズ1コア機能（ログイン〜学習〜成績可視化）を提供する。

## スコープ
- 対象期間: フェーズ1（〜9月末リリース想定）
- 対象機能: ログイン、本番クイズ（1日1回）、練習モード（無制限）、結果保存、個人成績ダッシュボード、月次ランキング生成
- 非対象: 管理者ダッシュボード拡張、CSV 出力、画像類似判定などフェーズ2以降の施策

## ビジネスゴール
- 新人スタッフが短期間で店舗接客に必要な商品知識を習得できる学習体験を構築する。
- 学習状況を店長が把握し、モチベーションを維持する仕組み（称号・ランキング）を提供する。

## ユーザーストーリー
- **新人スタッフとして**  
  日替わりの本番クイズで商品知識を復習し、正答率とヒント活用のバランスを改善したい。  
  なぜなら、10月までに接客で必要な商品説明ができるようになる必要があるから。
- **運用担当（店長・教育係）として**  
  スタッフごとのプレイ履歴とランキングを確認し、学習状況の遅れや強化ポイントを把握したい。  
  なぜなら、限られた時間で効率的に教育プランを組みたいから。

## 機能要件

### 要件1: ログインと認証
- USERS シートの ID / PASSWORD（または比較キー）でユーザーを認証し、称号や streak などの基本情報を取得する。
- 未登録ユーザーの場合はエラーメッセージを返す。
- ログイン成功後にホーム画面へ遷移し、ユーザー固有情報を表示する。
- 受入基準:
  - [ ] 正しい ID / PASSWORD（もしくは指定された認証キー）でログインするとホーム画面が表示される。
  - [ ] 誤った情報を入力した場合は認証エラーが表示され、シートに書き込みが発生しない。
  - [ ] ログイン直後にユーザーの称号・streak・未消化本番プレイ有無を表示できる。

### 要件2: 本番クイズ（daily モード）
- 1日1回限定で 10問の四択クイズを出題する。
- 各問題でカラコン画像・2種類のヒント（SPEC / コメント）を表示する。
- 回答後は即時に正誤と正解名称・ワンポイントを表示する。
- 受入基準:
  - [ ] ログイン済ユーザーが本番モードを開始すると 10問連続で出題される。
  - [ ] 各問題で 4択選択肢が表示され、選択すると正誤判定が行われる。
  - [ ] 本番モードは当日2回目以降開始できず、次回可能日時が表示される。
  - [ ] タイマー（20秒）が動作し、時間切れ時は不正解として処理される。

### 要件3: 練習モード（practice モード）
- 同一 UI で回数制限なくクイズを解ける。
- スコアは簡易表示とし、EXP/RP は本番より少ない（仕様通り）。
- 受入基準:
  - [ ] 練習モードでは日中いつでもクイズが開始できる。
  - [ ] 練習モードの結果は HISTORY に保存され、mode=`practice` として区別できる。
  - [ ] 練習完了後も本番プレイ可能回数は影響を受けない。

### 要件4: スコアリングと称号更新
- 正答率（最大100）+ ヒントボーナス（最大50）+ タイムボーナス（最大50）の合計 (0..200) を算出する。
- streak ブーストを考慮して EXP/RP を算出し、USERS シートに累積値・レベル・称号を反映する。
- 受入基準:
  - [ ] 各問題の正解状況・ヒント使用数・残り秒からスコアが計算され、合計スコアが UI に表示される。
  - [ ] HISTORY.metadata に accuracy / hintBonus / timeBonus / expEarned / rpEarned / streakAfter / levelAfter 等が保存される。
  - [ ] streak が継続するとブースト倍率が適用され、USERS シートの streak / points / level が更新される。

### 要件5: 回答ログ保存と重複防止
- HISTORY シート（v11 形式）に 1回答1行で書き込み、セッション合計スコアやメタ情報を保存する。
- 送信 API は多重送信による重複レコードを防止し、異常時はエラーを返す。
- 受入基準:
  - [ ] クイズ完了時に全10回答が HISTORY に正しい JSON メタ付きで保存される。
  - [ ] 送信リトライ時、同一セッション ID の重複登録が発生しない。
  - [ ] 保存失敗時は UI がエラーを通知し、再送処理を促す。

### 要件6: 個人成績ダッシュボード
- 直近最大10プレイの履歴、正答率/ヒント/タイム/EXP/RP の内訳、棒グラフによる推移を表示する。
- 本番/練習の区別および日付を表示する。
- 受入基準:
  - [ ] ログイン中ユーザーがマイ成績タブを開くと最新データが `google.script.run` 経由で取得される。
  - [ ] 直近10プレイ分のサマリがテーブルで確認できる。
  - [ ] EXP/RP の合計推移がグラフまたは棒チャートで視覚化される。

### 要件7: ランキング集計
- 週次/⽉次/年次（scope: weekly, monthly, yearly）ランキングを生成し、rankings シートに縦連結で保存する。
- ランキング API は指定された scope の上位ユーザーを UI に返す。
- 受入基準:
  - [ ] `updateRankingsAllScopes` 実行後、rankings シートに scope ごとのデータが出力される。
  - [ ] UI 初期表示で weekly ランキングが取得・表示される。
  - [ ] 同率（スコア同値）時の順位ルールを設計ドキュメント通りに適用する。

## 非機能要件
- **パフォーマンス**: UI の主要操作（ログイン、問題取得、結果送信）が 3 秒以内に応答すること。
- **安定性**: Apps Script 実行時エラーは Logger に記録し、ユーザーへは分かりやすいメッセージを返す。
- **モバイル最適化**: スマートフォン表示を優先したレイアウトで、主要操作が片手で完結する。
- **運用性**: 問題データ・称号・ランキング設定はスプレッドシート編集のみで更新可能とする。
- **セキュリティ**: WebApp が匿名公開設定のため、シート側で不要な列を公開せず、ログイン時に最低限の情報のみ返却する。

## 依存・前提条件
- Google Sheets 側に USERS / TITLES / HISTORY / 商品シートが正しいスキーマで存在すること。
- Drive 画像 URL が有効であり、Apps Script から参照できること。
- Apps Script プロジェクトが最新のトリガー（ランキング更新など）を設定済みであること。

## スコープ外・保留事項
- 管理者ダッシュボードでの高度な分析・CSV 出力はフェーズ2以降。
- 画像ベース類似判定、装用画像クイズは未対応。
- OAuth 認証やアクセス制御の強化は別途検討。
